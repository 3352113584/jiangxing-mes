## 6. A/B/C/D 生命周期 → 权限矩阵（NB-1 数据）

分类权威清单见设计文档 18 章（A=57 / B=48 / C=14 / D=12）。实现层规则：

| 类别 | mes_app 权限 | 业务更新路径 |
|---|---|---|
| A（正常可更新 57） | SELECT+INSERT+UPDATE | 普通 UPDATE（乐观锁 version 列） |
| B（append-only 48） | SELECT+INSERT；10 表白名单 UPDATE | 历史事实不改：状态推进走窄路径（T-9~T-14）或新事实/冲正/更正事件 |
| C（配置字典 14） | SELECT+INSERT+UPDATE | 旧版本停用不删（is_active=false） |
| D（事件/审计/导入史 12） | 仅 SELECT+INSERT | 一律 append-only |
| 全部 131 表 | DELETE=0 | 作废/失效=受控状态（INVALIDATED/VOID/voided/is_active=false） |

## 7. 幂等与并发控制实现

1. **client_token（网络层）**：部分唯一索引，同 token 重试落第二行被拒，应用层凭此 SELECT 返回原结果。
2. **action_key（业务动作层）**：`(task_id, action_key)` UNIQUE，并发重复提交仅一胜（F-1 实测）。
3. **report_seq（显示层）**：无唯一约束；发号经 `ref.code_rule` 行锁 `UPDATE seq_current=seq_current+1 RETURNING`，行锁串行保证不重不漏（F-5 实测）。
4. **库存底线**：`ck_stock_balance_weight_non_negative (weight_kg >= 0)`，并发超扣一成一败（F-3 实测）。
5. **冲正并发**：应用层守卫模式 `SELECT ... FOR UPDATE WHERE is_effective` + T-10 顺序要求（先 reversal_record 后翻转），败者零写入（F-4 实测）；重复冲正记录风险见 §8 GAP。
