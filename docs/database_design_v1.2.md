## 0. 设计总则（全文档统一约定）

### 0.1 命名规范

- 表/列名一律 `snake_case`；表名单数；禁止保留字；禁止 `pg_`/`sql_` 前缀。
- 主键列一律 `id`；外键列 = `<目标实体单数>_id`（如 `actual_component_id`）；软引用对 = `<语义>_ref_type` + `<语义>_ref_id`。
- 状态列名 `status`（实体内唯一状态）或 `<域>_status`（多状态共存时，如 `production_status` / `quality_status`）。
- 枚举类型命名 `enum_<实体>_<列>`；字典表 `ref.<名>`。
- 审计列统一四元组：`created_by / created_at / updated_by / updated_at`（A 类）；事实/事件表加 `occurred_at`（业务发生时刻，可补录但必填）与 `recorded_at`（系统落库时刻，DB 默认 now()）。

### 0.2 主键与标识（plan 第 4 节落地）

- 全部物理表：`id BIGINT GENERATED BY IDENTITY PRIMARY KEY`。**无 UUID**。
- 业务编号（project_code / material_code / issue_no / qr_code / shipment_no 等）为 UNIQUE 非主键列，发号经 `ref.code_rule`（序列值持久化，`SELECT ... FOR UPDATE` 行锁发号）。
- instance_sequence：INT，由服务层按 (subproject, component_no) 维度只增发放，DB 唯一键兜底。
- `client_token`：提交类事实表幂等键，`VARCHAR(64)` + 部分唯一索引（见 0.6）。

### 0.3 引用三分离（plan 第 5 节落地，全文档执行）

| 概念 | DB 实现 | 示例 |
|---|---|---|
| **Mandatory FK** | `BIGINT NOT NULL REFERENCES ... ON DELETE RESTRICT` | import_row→import_batch |
| **Optional FK** | `BIGINT NULL REFERENCES ... ON DELETE RESTRICT`（仍是真 FK） | production_task.supplier_id、surplus_material.parent_surplus_id |
| **Polymorphic Soft Reference** | `ref_type VARCHAR(32) CHECK (IN 受控清单) + ref_id BIGINT`，**无 FK**；(ref_type, ref_id) 建索引；受控清单逐表声明 | import_row.target_*、material_issue_document.issue_to_*、correction_request.source_* |

可空语义一律用 Optional FK 表达，**不降级为软引用**；软引用只用于"多目标类型"场景。

### 0.4 只追加与不可变性（模型 11 章落地）

- **B/D 类事实表（append-only）**：业务账号回收 `UPDATE/DELETE` 权限（角色级 revoke）；更正走更正域（correction_request → approval → entry/reversal）。
- **A 类当前值表**：允许 UPDATE，但被事实引用后的关键列进入"事实后 immutable"（见 19 章）；主数据删除=软删除（`is_active=false` 停用标记），物理 DELETE 一律禁止。
- 模板行不可变（约束 24）：`bom_template_line` / `route_template_step` 引用计数>0 后业务语义列禁改——DB 层用触发器拦截 UPDATE（Phase 3 实现），文档在逐表 Immutability 节声明。

### 0.5 枚举 vs 字典（plan 第 9 节判定结果）

| 判定为 | 清单 |
|---|---|
| **PG ENUM**（封闭、系统演进、无需业务日常维护） | 项目八态、构件生产状态、构件质量状态、任务状态、检验单状态、设备状态、异常状态、托盘状态、集装箱状态、发运状态、预留状态、导入批次状态、导入行 result_status、import_kind、make_type、line_status/step_status、part_instance 状态、team_membership 归属类型、issue_to 类型等受控 type 列 |
| **ref 字典表 + FK**（业务可增删停用、有描述/排序/统计标记） | operation_type、inspection_type、exception_category、component_type_dict、component_feature_dict、subproject_type、reason_dictionary、unit_of_measure、code_rule、system_config、qr_scan_access、**acceptance_result（N-2 受控值域）**、component_type_mapping（映射配置） |

状态机**迁移合法性**由服务层控制；DB 层只做值域约束（ENUM）+ 事件行留痕。10 套状态机落点见 14 章。

### 0.6 幂等模式（plan 第 12 节落地）

- 提交类事实表统一：`client_token VARCHAR(64) NOT NULL`（扫码端生成 UUID），`CREATE UNIQUE INDEX ... ON t(client_token) WHERE client_token IS NOT NULL`（部分唯一索引，人工补录可空）。
- 重试语义：同 token 重复提交 → 服务层捕获唯一冲突 → 返回首次结果（首次结果按 token 反查原行）。
- 业务防重键兜底见各表 Idempotency 节；导入行幂等 = `(import_batch_id, source_identity)` 唯一（source_row_number 不参与，约束 29）。

### 0.7 并发模式（plan 第 11 节落地）

- A 类聚合根加 `version INT NOT NULL DEFAULT 1` 乐观锁（清单见 18 章）；更新语句带 `WHERE version = :v` 并 `version = version + 1`。
- 关键互斥事务用 `SELECT ... FOR UPDATE` 锁聚合根行（装载锁构件、装柜锁托盘、发运确认锁范围）；隔离级别默认 READ COMMITTED。

### 0.8 通用列模板

- A 类表标配：`id, …业务列…, is_active BOOLEAN DEFAULT TRUE（主数据）, created_by, created_at, updated_by, updated_at, version`。
- B/D 类事实表标配：`id, …事实列…, occurred_at NOT NULL, recorded_at NOT NULL DEFAULT now(), created_by`。
- 数字精度：重量 `NUMERIC(12,3)`（kg，3 位小数——兼容 6514.655 类清单值舍入差）；长度 `NUMERIC(10,2)`（mm）；数量（件）`INT`；金额/单价仅登记 `NUMERIC(14,2)`（不做财务）。

## 15. 状态机 10 → 物理落点（State Machine Coverage）

| # | 状态机 | ENUM（PG ENUM） | 事件/历史载体 | 迁移控制 |
|---|---|---|---|---|
| 1 | 项目（主/子同套八态） | `enum_project`：draft/preparing/production/paused/production_complete/shipping/completed/closed | `md.main_project.status`、`md.subproject.status` + `aud.project_status_history`（from/to/reason_category_id/reopened_reason/reopened_to_state） | 服务层校验角色/审批配置；**每次迁移必写历史行**；closed→活跃重开必填 reopened_reason（模型 10.1） |
| 2 | 构件生产+质量（双态独立） | `enum_ac_production`（not_started…site_received+scrapped）、`enum_ac_quality`（pending_inspection…final_qualified） | `prod.actual_component.production_status` / `quality_status` + `prod.actual_component_event`（payload JSONB） | 事实聚合建议+系统自动迁移；**releasable/shippable=服务层推导**（production_completed ∧ final_qualified ∧ 非 scrapped），包装/装托/装柜/发运事务硬校验；两状态机互不写对方（RED-09） |
| 3 | 任务 | `enum_task_status`：pending/in_progress/paused/completed/cancelled | `prod.production_task.status` + `prod.task_event`（start/pause/resume/complete/cancel）+ `task_cancellation` | 暂停/恢复/取消全写事件；取消=主管权限+审批记录；**返工=新任务（rework_of_task_id），老任务状态不改**（10.3） |
| 4 | 检验单 | `enum_inspection`：registered/inspecting/concluded（+`conclusion` pass/fail 可空） | `prod.quality_inspection.inspection_status`；检验行自身 append-only；**复检=attempt+1 新行** | 结论出具后触发器禁 UPDATE（改判走更正域）；最终合格以 `final_qualification` 放行为准（10.4） |
| 5 | 设备 | `enum_equipment`：running/stopped/fault/under_maintenance | `md.equipment.status` + `prod.equipment_event`（from_status/to_status） | 事件驱动迁移；fault 后经 `equipment_impact` 关联受影响任务（10.5） |
| 6 | 异常 | `enum_exception`：open/processing/closed | `aud.exception_event.status` + `aud.exception_handling`（closed 前可多条） | 关闭必填关闭信息（服务层）；一因多果经 `exception_impact`，禁止复制异常（10.6） |
| 7 | 托盘/集装箱 | `enum_pallet`：empty/in_use/loaded/in_container；`enum_container`：empty/loading/sealed/shipped/returned | `ship.pallet.status`、`ship.shipping_container.status` + `pallet_load_history`（load/remove/repack）、`container_load_history`（load/unload/reload） | **repack 是事件非状态**；跨主项目装载前须有效 `mixed_load_authorization`（10.7） |
| 8 | 发运 | `enum_shipment`：draft/confirmed/in_transit/delivered/returned | `ship.shipment.status` + `shipment_event`（confirm/depart/transit_node/arrive/sign/return/reship）+ `shipment_snapshot` | **confirmed=快照生成事务**；confirmed 后快照冻结无更新路径；退运旁路；补发=新 shipment 行（10.8） |
| 9 | 更正申请 | `enum_correction`：draft/submitted/approving/approved/applied/rejected | `aud.correction_request.status` + `correction_approval`（分级链）+ `reversal_record` | **被下游引用时 approved ⇒ 必生成 reversal_record**（原事实标冲正+反向/重做关联）（10.9） |
| 10 | 库存预留 | `enum_reservation`：reserved/allocated/consumed；旁路 released/cancelled | `whs.material_reservation.status` + `consumed_by_ledger_id`（核销关联） | **任何状态不产生 stock_ledger、不改 stock_balance**（MCR-5）；迁移经服务层 version CAS |

> 状态机 10 留痕设计决策（模型 9 章授权"是否独立成表详设定"）：**不建独立预留事件表**，迁移留痕经 `aud.operation_log`（target_ref=reservation，detail 含 from/to/操作人/原因）+行 version CAS。若架构审查要求独立事件表，属 Phase 3 前局部增补，不影响主体结构。

## 17. 并发与幂等专章

### 17.1 乐观锁 version 列清单（A 类聚合根）

`main_project`、`subproject`、`material`、`supplier`、`warehouse`/`storage_location`、`production_task`、`stock_balance`、`material_reservation`、`surplus_material`、`pallet`、`shipping_container`、`equipment`。更新模式：`UPDATE ... SET version=version+1 WHERE id=:id AND version=:v`；影响行数=0 ⇒ 并发冲突，应用层重读重试（有限次，默认 3）。

### 17.2 client_token 幂等清单（0.6 部分唯一索引模式）

| 表 | 幂等键 | 业务兜底 |
|---|---|---|
| production_report | client_token 部分唯一 | (task_id, report_seq) 唯一 |
| material_consumption | client_token 部分唯一 | (part_instance_id) WHERE is_effective 唯一 |
| site_delivery_record | client_token 部分唯一 | （多次签收合法，无业务兜底键） |

### 17.3 网络抖动专项（手机 4G/5G 重复发送）

同一扫码动作重复提交的行为契约：

1. **生产确认**：终端超时重试携带同一 client_token ⇒ 部分唯一索引拦截第二行 ⇒ 服务端捕获冲突后**查询首次落库结果原样返回**（幂等响应，非报错）。`production_report` 永不出现两行同动作 ⇒ 完成数量=COUNT(事实行) 天然不重复（RED-07）。
2. **材料消耗**：`material_consumption.client_token` 同模式 ⇒ 不会重复消耗；有效消耗唯一约束兜底防一料多记。
3. **库存过账**：stock_ledger 行由服务端动作在 consumption/issue 确认事务内一次生成；上层幂等截停后重试不会重复触达过账。
4. **领料实发**：`issue_line.issued_qty` 为流水聚合可重建值，重复过账行即使发生也会在聚合对账中暴露（双保险）。

### 17.4 事务隔离与行锁

- 全局隔离级别 **READ COMMITTED**（PG 默认）。
- `SELECT FOR UPDATE` 行锁清单：
  - `ref.code_rule.seq_current`——发号（独立短事务，防跳号/重号）；
  - `whs.stock_balance` 扣减行——先锁余额行→写流水→`CHECK (weight_kg >= 0)` 兜底；
  - `ship.pallet` 装载事务——锁托盘行+聚合称重事实校验 max_weight（约束 10）；
  - `prod.component_list_item` 实例化——锁清单行防并发双实例化（实例三元组唯一兜底）；
  - `prod.actual_component`+`route_template_step` 维度——任务 attempt 分配（三元组唯一兜底）。

### 17.5 重试行为总表

| 冲突类型 | 行为 |
|---|---|
| client_token 唯一冲突 | 返回首次结果（幂等，200） |
| version 乐观锁冲突 | 重读→重试（≤3 次）→超限人工介入 |
| 业务唯一键冲突（发号/编码） | 重新取号/提示人工 |
| 死锁 | 随机退避后重试（≤2 次） |

## 19. 业务场景 A~J → 数据库级验证

> 每个场景给出：涉及表 / 关键约束 / 预期结果。全部场景均可在 Phase 3 用测试数据按表级断言复验。

### 19.A 正常生产（quantity=9 → 9 构件 + 36 零件实例）

- **涉及表**：imp.component_list_import_batch → imp.import_row → prod.component_list_item → eng.component_bom_template/bom_template_line → prod.actual_component → prod.part_instance → prod.production_plan(+version/line) → prod.production_task → prod.production_report(+worker/measure) → prod.quality_inspection → prod.final_qualification → whs.finished_goods_stock(+event)
- **关键约束**：`(subproject_id, component_no)` 唯一；`(subproject_id, component_no, instance_sequence)` 唯一；actual_component 无 quantity 列；part_instance 三元组唯一；plan_line 三元组唯一；task 三元组唯一；report `(task_id, report_seq)` 唯一+client_token；finished_goods 部分唯一 WHERE in_stock
- **预期结果**：清单 quantity=9 ⇒ 9 行 actual_component（sequence 1..9）；BOM 模板行 P1×4 ⇒ 每构件 4 行 part_instance（共 36）；完成件数=COUNT(状态∉{scrapped,cancelled})=9；需求恒=9；最终合格后成品入库 1 行/件

### 19.B 报废补做（AC05 报废 → AC11 补件）

- **涉及表**：prod.component_scrap_record、prod.actual_component（新行）、prod.actual_component_event、aud.approval_record
- **关键约束**：`(actual_component_id) 部分唯一 WHERE is_effective`（一构件至多一次生效报废）；`replacement_for` 单值唯一+指向态 ∈ {scrapped, cancelled}（触发器/服务层）；sequence 只增不复用
- **预期结果**：AC05 置 scrapped 留史（需求实例槽位保留）；AC11 sequence 续号、`replacement_for=AC05`；需求仍=清单 quantity 不膨胀；完成=COUNT(有效)=10/10；报废=1

### 19.C 返工（焊接 failed → NCR → attempt 2）

- **涉及表**：prod.quality_inspection（failed）→ prod.ncr → prod.rework_order → prod.production_task（attempt+1、rework_of_task_id）→ prod.production_report → prod.quality_inspection（attempt+1）→ prod.final_qualification
- **关键约束**：task 三元组 `(actual_component_id, route_template_step_id, attempt)` 唯一；`rework_of_task_id` self FK；检验 `(actual_component_id, inspection_type_id, attempt)` 唯一；原检验/任务行 append-only
- **预期结果**：焊接 step 新建 attempt=2 任务（老任务保留 completed+failed 检验）；**切割 attempt 完全不受影响**；复检=新检验行；最终合格以 final_qualification 放行

### 19.D 领料 10T / 消耗 7.8T（差额 2.2T 余料）

- **涉及表**：whs.material_issue_document → material_issue_line（requested 10t）→ whs.stock_ledger（issue 行，issue_line_id 反向，可 6t+4t 两行）→ whs.stock_balance（扣减）→ whs.material_consumption（7.8t）→ whs.surplus_material（2.2t，source_batch_id）
- **关键约束**：issue_line.material_batch_id NOT NULL；`stock_ledger.issue_line_id` 可空（一行 0..N 流水）；`stock_balance.weight_kg CHECK >= 0`；consumption `(part_instance_id) WHERE is_effective` 唯一；单据≠流水（ledger 无单头语义）
- **预期结果**：单据 10t / 流水合计 10t / 消耗 7.8t / 余料 2.2t **四个对象独立成行、互不冒充**；差额自动成余料且血缘可溯；余额=原值−10t

### 19.E 余料递归（A→B→C→D）

- **涉及表**：whs.surplus_material（4 行）+ whs.material_consumption（source_kind='surplus'）+ whs.stock_ledger（surplus_in/surplus_issue）
- **关键约束**：`parent_surplus_id` self FK + `CHECK (id <> parent_surplus_id)`；**循环禁止=事务/应用层递归校验（CHECK 无法表达递归——如实声明）**；`source_batch_id` NOT NULL 恒必填
- **预期结果**：A→B→C→D parent 链逐级建立；任一代 `source_batch_id` 一步直达原始 Heat（不断链）；插入时应用层沿 parent 链回溯校验祖先集合无环；出池/再入池写事件行不改原行

### 19.F 内部/外协混合（同构件切割 inhouse、焊接 outsource）

- **涉及表**：prod.production_task（多 step 多行）+ md.supplier + md.team + prod.task_participant
- **关键约束**：`make_type` NOT NULL；条件 CHECK（outsource⇒supplier_id 非空、inhouse⇒必空）；`execute_team_id` 单值；supplier 与 execute_team/worker 三分立禁共指（服务层）
- **预期结果**：制造方式为**任务级**事实；同构件不同 step 可异构；任务创建后 make_type/supplier 不可改；attempt1 保留原值

### 19.G Excel 修正版（corrected_resubmit）

- **涉及表**：imp.component_list_import_batch（import_kind='corrected_resubmit'、supersedes_batch_id）→ imp.import_row（同 source_identity 新行、corrected_from_row_id）→ imp.import_correction_result → prod.component_list_item / actual_component
- **关键约束**：`(import_batch_id, source_identity)` 唯一；`CHECK (supersedes_batch_id 非空 ⇒ import_kind='corrected_resubmit')`；`source_row_number` 不参与唯一；conflict 人工决策；实例三元组幂等复用
- **预期结果**：原批次/原行**不删除不覆盖**（新行新身份）；无生产事实构件自动更新；有生产事实构件 ⇒ conflict ⇒ 人工决策；同 source_identity 内容变化经 content_fingerprint 识别为 updated

### 19.H 一单多行领料（一张单 5 种材料）

- **涉及表**：whs.material_issue_document（1 行）+ material_issue_line（5 行，不同 batch）+ whs.stock_ledger（N 行）
- **关键约束**：`issue_no` 全局唯一；`(issue_document_id, line_no)` 唯一；line.material_batch_id NOT NULL
- **预期结果**：经单头全部可达；**每行 0..N 条流水**（未过账中间态合法）；行≠流水（G-1）

### 19.I 一 PO 三车到货

- **涉及表**：whs.purchase_order(+item) → purchase_receipt×3（trip_no/vehicle_plate）→ purchase_receipt_item（N 行）→ 验收 → material_batch
- **关键约束**：`receipt.purchase_order_id` 可空 FK（一 PO 多车次）；trip_no/vehicle_plate 为车次信息列；**登记不产生任何库存事实**（约束 32）
- **预期结果**：三车三单独立登记/独立验收；到货预告不入库；验收前无 batch/无 ledger

### 19.J 一车多 Heat（同车 5 种材料 2 合格 3 待处理）

- **涉及表**：whs.purchase_receipt（1 行）+ purchase_receipt_item（5 行独立结论）→ material_batch（2 行，仅合格行）+ material_batch_certificate
- **关键约束**：`(supplier_id, heat_no)` 组合唯一；**批次生成唯一入口=验收事务**；一车多 Heat 不归并
- **预期结果**：2 合格行生成 2 个 material_batch（不同 heat_no=不同批次行）；3 待处理行不生成批次（acceptance_result=NULL 中间态合法）；质保书经 junction 关联；车头不做任何 Heat 归并
