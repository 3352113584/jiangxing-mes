## 四、Docker 网络结构

```
Internet
   │  HTTPS/443（HTTP/80 → 443 跳转）
   ▼
┌─────────────┐
│  gateway    │  nginx:1.27-alpine  (ports: 443, 80)
│  (nginx)    │
└──────┬──────┘
       │  /api/  → backend:8000
       │  /      → 静态前端 (挂载 frontend-dist)
       ▼
┌─────────────┐        ┌──────────────────────┐
│  backend    │ ─────▶ │  postgres:5432        │
│  (uvicorn)  │ 内部    │  仅 mes_net 内部网络   │
│  mes_net    │ 网络    │  无公网端口映射        │
└─────────────┘        └──────────────────────┘

网络：mes_net (bridge)。所有服务均连入 mes_net。
postgres 不设置 ports；backend 不设置 ports；gateway 仅发布 443/80。
```

## 七、HTTPS 方案

- 网关 `nginx` 监听 443（TLS）与 80（跳转）；TLS 证书来自宿主机 `./certs` 挂载（只读）。
- 协议 `TLSv1.2/1.3`，`HIGH:!aNULL:!MD5`；启用 `Strict-Transport-Security`。
- 证书更新：由宿主机 `certbot` 等工具续期后覆盖 `./certs`；建议权限 `600`、属主 `root`。
- 后端 `uvicorn` 不直连公网，所有流量经 `nginx` TLS 终止后明文转发内部网络。

---

## 八、PostgreSQL 隔离方案

- `postgres` 仅连入 `mes_net`，**不设置 `ports`**，因此 5432 仅在容器网络可见，绝不映射宿主机/公网。
- `backend` 通过服务名 `postgres:5432` 连接（同网络 DNS 解析）。
- `gateway` 不配置任何到 `postgres` 的代理。
- 数据持久化：命名卷 `mes_postgres_data`（本地卷，不入库）。
