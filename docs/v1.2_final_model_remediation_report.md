## 3. G-1 / G-2 完成情况

### G-1 领用单据事实 → ✅ CLOSED

- **复用检查（先行）**：模型无通用单据头/行结构可复用——purchase_receipt/receipt_item 为采购域专用，nesting、import 各自成对；故按最小结构新增。
- **新增**：`material_issue_document`（单头：issue_no 全局唯一、开单时间、开单人、领料对象/执行主体=对象类型+ID 软引用、项目/子项目上下文可空=车间通用领料）+ `material_issue_line`（行：→material_batch 必须、→storage_location 可空、数量/重量、↔stock_ledger 领用行 1—0..N）。关系 93~97，约束 30，唯一键 issue_no。
- **重点不变量**：stock_ledger 不承担"领料单头"职责；一张多材料领料单=一个单头+多行全部可达；**单据≠流水≠消耗三分立**。

### G-2 材料主数据唯一身份 → ✅ CLOSED

- **证据**：真实原材料字典 **221 组同名称同规格不同材质** → name+specification 不可作唯一身份。
- **落点**：material.`material_code`（系统管理全局唯一业务身份，约束 33，唯一性表，编号体系）；键形态裁决=**独立材料编码**（非含材质组合键）。
- `supplier_material_code` 可空承载供应商原始编码快照，与 MES 内部身份分离、不覆盖标准主数据；材质/牌号必含属性；management_class 开放字典（原材料/周转物料/固定资产/配件/耗材/劳保）。不建编码治理平台。

## 4. R61 到货车次完成情况 → ✅ CLOSED

- **复用检查（先行）**：receipt/goods_receipt/inbound_receipt/arrival 等结构逐一排查——`purchase_receipt`（+receipt_item）结构完全匹配"车次+明细"，**复用不新增实体**。
- **语义冻结**：purchase_receipt = **到货车次**（一次到货一张单=一个车次）；增 `trip_no`（车次号）、`vehicle_plate`（车牌），均可空。
- **结构承载**：关系 15 = 一个采购订单→多个到货车次；关系 16 = 一个车次→多个材料明细；关系 17 = 一车拆多炉批（一车两 Heat=两行 receipt_item→两个 material_batch，**不因同车合并批次**）。**车次 ≠ material_batch/Heat ≠ 库存单位**。
- **到货/收货边界冻结（约束 32）**：到货预告（**不建实体**——微信群只是通知来源，不建微信通知表）→ 到货车次（purchase_receipt）→ 正式收货/验收（receipt_item 验收结论）→ 库存入账（stock_ledger 入库行）→ 实际消耗（material_consumption）。**到货预告不改 stock_balance、不产生 material_consumption、不生成 material_batch；批次生成唯一入口=receipt_item 验收**。
- 同步闭环仓库影响审查 V-1（到货通知事实落地）。
