## 4. 价格版本机制（不可破坏的历史）

- **不可变历史版本**：已生效（effective_from ≤ 今天）的版本**冻结**，改价语义 = 关旧版本 + 开新版本（时间旅行回放用）。
- **单一当前**：`uq_pop_current WHERE is_current` 部分唯一索引保证全局仅一个当前版本；T-17 在 INSERT/UPDATE 当前版本时关闭其它 current。
- **时间旅行**：视图按 `occurred_at::date` 在区间内匹配价格（取 effective_from 最大者），历史报告永不被新价回写。
- **T-17 触发器 `mes_t17_price_version_guard`**（**未引入 btree_gist**）：
  - `pg_advisory_xact_lock(project_operation_id)` 事务级串行化，并发改价不会产生两个当前版本；
  - 已生效历史版本：**禁止 UPDATE / DELETE**；
  - 生效区间**不重叠**（与同 po 其它版本闭开区间相交即拒绝）；
  - 当前开放版本：**仅允许关闭**（改 effective_to / is_current），禁止直接改价/区间；
  - 未来版本（effective_from > 今天）：一般自由编辑/删除；
  - **【审查新增】被生产事实引用的版本不可变**：新增函数 `mes_po_price_is_referenced(po, eff_from, eff_to)`，判定是否存在 `production_report` 落入该版本生效窗口、且所属 task 解析到的 project_operation 正是本版本 po；**一旦被引用（无论是否已生效），禁止 UPDATE 价格/口径/生效起始日/归属、禁止 DELETE**；仅允许不切断已引用事实的「关闭」（effective_to ≥ 最大已引用事实发生日，且不得重新开放置空）。强制在数据库触发器层，优先于应用层。

## 5. 五种计价口径实现

| 口径 | 度量来源（优先级） | 回退 / 缺失 |
|---|---|---|
| `weight` | `production_measure(weight)` → 回退 `actual_component.actual_weight` | 回退标 `MEASURE_FALLBACK`；两者皆缺 → `MISSING_MEASURE` |
| `piece` | 冻结：1 任务 × 1 正常 attempt = 1 件；**禁止 COUNT(production_report)** | — |
| `length` | `production_measure(cut_length+weld_length+mach_length)`（=冻结 V1.2 `basis_length_mm` 统一长度计量；三子类型为 schema 既有定义，非实现发明） | 0 → `MISSING_MEASURE` |
| `hour` | `SUM(production_report_worker.work_hours)` → 回退 `production_measure(hours)` | 0 → `MISSING_MEASURE` |
| `hole_count` | `production_measure(hole_count)` | 0 → `MISSING_MEASURE` |

> **计价粒度（审查修订）**：物理计量（weight/length/hour/hole_count）在**每个 production_report 粒度**匹配当时有效的 `project_operation_price`（按该报告自身 `occurred_at` 时间旅行），再跨报告 SUM —— 不再以 `MAX(report.occurred_at)` 给整个 task 统一套价（修正跨价格版本历史计价风险：3 月 5t×100 + 5 月 5t×120 = 1100，而非 10t×120=1200）。件计价（piece）身份仍以 (构件, 工序, 正常 attempt)=1 件 为准（task 粒度），价格按 task 代表发生时间（MAX(report.occurred_at)）匹配。视图最终仍输出**每任务 1 行**，`WHERE EXISTS report`，满足「禁止按报告重复计数；1 任务×1 正常 attempt=1 件」。

## 6. 正常 / 返工 / 报废口径

- **正常成本** `normal_cost`：`attempt = 1`（且 `rework_of_task_id IS NULL`）。
- **返工成本** `rework_cost`：`attempt > 1`（`is_rework = (attempt>1 OR rework_of_task_id NOT NULL)`）。
- **返工绝不覆盖 / 作废 / 删除正常事实**：两行独立存在于 `v_operation_cost_trial`，汇总层 `normal_count/rework_count/normal_cost/rework_cost/total_cost` 分列。
- 报废（`scrap`）：由 `component_scrap_record` 等既有实体承载，本模型不重复定义，成本口径按「未登记完成即不计入已完工会结算」处理（与冻结规则一致）。

### 16.1 同一 production_task 跨价格版本时的计价粒度
- **问题**：原 `v_operation_cost_trial` 以 `production_task` 为粒度，跨任务全部报告聚合度量，`occurred_at` 取 `MAX(report.occurred_at)`，再用这一单一时间匹配价格。风险示例：同一 task 在 3 月（5t×100）与 5 月（5t×120）两份报告，会因 MAX=5 月让整 task 10t 全按 120 计价（=1200，错误）。
- **修复**：物理计量（weight/length/hour/hole_count）改为**每个 production_report 粒度**——每个报告用自身 `occurred_at` 匹配当时有效的 `project_operation_price`，再跨报告 SUM。件计价（piece）身份仍以 (构件, 工序, 正常 attempt)=1 件 为准（task 粒度），价格按 task 代表发生时间匹配。
- **验证**：新增 `test_same_task_reports_cross_price_versions`，同一 task 两份跨版本报告 = 5×100 + 5×120 = 1100（正确）；既有 `test_price_time_travel` / `test_partial_report_no_double_count` 仍 PASS。

### 16.2 未来价格一旦被生产事实引用即不可变
- **问题**：原 T-17 未来版本（effective_from > 今天）可自由编辑/删除，未考虑其可能已被生产事实引用。

### 16.3 length 口径核实（Issue 4）
- 核实结果：`prod.production_measure.measure_type` 在冻结 V1.2 schema（`docs/database_design_v1.2.md` §production_measure）已定义为 `CHECK(weight/cut_length/weld_length/mach_length/hours)`；三子长度类型系** schema 既有定义**，非实现时自行发明。
- 业务上统一长度计量 = `basis_length_mm`（计价长度基数）= 切割长度 + 焊缝长度 + 加工长度之和，即 `cut_length + weld_length + mach_length`。
- **结论**：保留 `price_basis=length → production_measure(cut_length+weld_length+mach_length)`，并在本报告中明确说明；**不回退**到单一 `length` 字段（schema 无此 measure_type，回退将改动冻结 schema 且违背「不自行改变业务定义」）。
