## 13. 冻结的架构不变量（Phase 2 必须全部继承，不得弱化）

| # | 不变量 | 内容 |
|---|---|---|
| 1 | 构件 | 一件物理构件一个 actual_component 实例（无 quantity 列，需求量只在 component_list_item） |
| 2 | 材料 | 默认按 material + batch/Heat + inventory unit 追溯；不强制逐块/逐根（约束 34） |
| 3 | 仓库 | issue ≠ consumption（单据≠流水≠消耗三分立，约束 30） |
| 4 | 余料 | 必须有 parent_surplus_id 父子血缘 + source_batch 终极来源（约束 26） |
| 5 | 工程 | 历史引用不可漂移（模板行不可变+停用式演进，约束 24/25） |
| 6 | 导入 | source_identity ≠ row_number（约束 29；row_number 仅定位） |
| 7 | 预留 | reservation 不产生库存流水、不改余额（约束 31 / 10.10） |
| 8 | 发运 | 历史 snapshot 不可变（发运确认冻结事实） |
| 9 | 生产 | production complete ≠ quality release（双状态机独立，releasable 服务层推导） |
| 10 | 返工 | 不得重复计产（attempt 链 + 统计只看构件有效终态，RED-11） |

## 14. 冻结后修改规则

- 冻结后**不得随意修改 Domain Model**；
- Phase 2 中发现**字段类型 / 索引 / PostgreSQL 实现方式 / ORM 映射 / SQL 实现 / 性能问题**：可在 Phase 2 内处理；
- 发现**业务语义本身错误**：必须重新开启架构变更流程（修订模型 → 复审 → 重新冻结），**禁止 Phase 2 随手修改业务语义**；
- 唯一例外触发条件：真正阻断性的架构错误。
