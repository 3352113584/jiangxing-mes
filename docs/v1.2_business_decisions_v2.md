# 第一部分 新增确认：主项目 / 子项目结构（新规 P 系列）

## P-1 项目层级：主项目 → 子项目 → 构件号（清单） → 实际构件

- 真实工程不是"项目→构件"两层，而是四层：
  主项目（如 XX海外钢结构项目）→ 子项目（1号厂房、2号厂房、办公楼、设备区、A区、B区…）→ 构件清单中的构件号（GZ1-001）→ 实际构件（GZ1-001-1、GZ1-001-2…）。
- 先建主项目，再在其下建多个子项目。
- 子项目**不是普通分类字段**，而是主项目下的**独立结构业务单元**（各子项目基本结构不同）：可独立进入、独立维护、独立查看进度，但不能脱离主项目成为独立数据体系。

## P-2 子项目独立管理的内容（每个子项目各自一页）

构件清单、零件清单、材料需求、下料/排版（套料）、**生产计划与任务安排**、生产过程、质量记录、成品、包装、装柜、发货/物流、完成重量、计划与实际进度。

## P-3 主项目汇总职责

主项目层只做跨子项目的汇总与穿透查看：总构件数、总重量、总体生产进度、总体质量进度、总体装箱量、总体发运量；可下钻进入任一子项目查看自己的构件、重量、进度、质量、装箱、发运。

## P-4 构件归属与追溯链（第三轮修订）

- **构件清单记录、实际构件、零件都直接归属到子项目**；主项目归属由子项目上溯得到，不作为独立录入的主数据事实。
- 完整追溯链：**主项目 → 子项目 → 构件清单记录（构件号）→ 实际构件 → 零件**。
- 任一实际构件必须可沿该链追溯；其全部过程数据（见 P-9）独立持有。

## P-5 托盘边界（修正老板问卷第 9 题，即 J-09 / Q-18；示例编号第三轮同步）

- 一个托盘**默认只属于一个主项目**；
- **允许**同一托盘装该主项目下不同子项目的构件（例：P001 同时装 1号厂房的 GZ1-001-1 和 2号厂房的 HZ2-1-1）；
- **不允许**不同主项目构件默认混装；
- 必须记录托盘中每个实际构件所属的子项目，可按子项目统计件数、重量、明细；
- 超承重**硬拦截**（不变）；
- 特殊情况确需跨主项目混装：必须授权 + 完整记录。

## P-6 集装箱边界（修正老板问卷第 10 题，即 J-10 / Q-21）

- 一个集装箱**默认只属于一个主项目**；
- **允许**装该主项目下不同子项目的构件/托盘（例：C001 内含 1号厂房 P001/P002、2号厂房 P003、办公楼 P004）；
- **不允许**不同主项目默认混装；一主项目可多箱；一箱可多托盘；
- 记录托盘与构件所属子项目；扫码可见 主项目→子项目→箱→托盘→构件 完整层级；
- 退运/补发留历史、箱体循环使用、发运确认固化清单（均不变）；
- 特殊跨主项目混装同样需授权 + 留痕。

## P-7 现场扫码层级（第三轮补充实际构件层）

- 集装箱码：主项目 → 子项目 → 集装箱 → 托盘 → 构件；展示项目、子项目、箱号、托盘、构件数量/编号、重量、发运状态、目的地等。
- 构件码：主项目 → 子项目 → 构件号（清单）→ 实际构件编号 → 重量 → 生产状态 → 质量状态 → 当前托盘 → 当前集装箱 → 安装位置。
- 安装位置来自图纸/构件清单基础数据，普通现场人员默认只读、不允许随意修改（J-02/Q-02 口径不变）。

## P-8 三个概念必须区分（第三轮新增，已确认事实）

1. **构件清单记录**：表示设计/订单"要求生产什么构件、数量多少"。它是一行清单，含计划数量（quantity），**本身不是物理件**。
2. **构件号**：清单中的基础业务编号，如 GZ1-001。
3. **实际构件**：真正生产出来的一件物理构件，如 GZ1-001-1、GZ1-001-2、GZ1-001-3。

关键事实：
- 同一子项目内，构件号相同、名称相同但数量大于 1 是正常情况：清单只有一行（GZ1-001，数量 5），不得当成 1 个实际构件，必须生成 5 个实际构件。
- **跨子项目允许相同构件号**：1号厂房的 GZ1-001-1 与 2号厂房的 GZ1-001-1 是两个不同的实际构件，允许同时存在。
- **绝对禁止"整个主项目范围内构件号必须唯一"的规则。**
- "数量（quantity）"语义：只出现在**构件清单记录**（计划数量）以及生产/质量等汇总事实上；**实际构件是物理件本身，不再设置"数量"字段表示多件**（一件就是一条记录，数量恒为 1 的语义）。

## P-9 实际构件的生成与编号规则（第三轮新增，已确认业务方向）

- 生成规则：清单记录 GZ1-001、数量 3 → 系统自动形成 3 个实际构件 **GZ1-001-1、GZ1-001-2、GZ1-001-3**。
- **数量为 1 也生成带序号的实际构件：GZ1-001-1**。不允许"数量 1 一套规则、数量大于 1 另一套规则"，编号规则永远统一。
- 业务唯一键：**子项目 + 构件号 + 实际件序号**（示例：1号厂房+GZ1-001+1 与 2号厂房+GZ1-001+1 可并存）。
- 显示编号 = 构件号 + "-" + 实际件序号（老板示例为 -1、-2、-3；序号是否补零对齐如 -01 属显示格式细节，由项目组定，见 C-13）。
- 二维码：业务编号允许跨子项目肉眼同号，但**二维码在系统内必须技术全局唯一**（由 主项目码+子项目码+实际构件 组合解析），扫码自动定位到唯一实际构件。
- 报废/补件：原"报废序号不重用、补件续新序号"规则保留（在同一子项目+构件号内续排，如 5 件中 1 件报废补做 → 序号 6）。
- 每个实际构件独立拥有（独立到件，不与同号其他件共享）：
  独立二维码、独立生产履历、独立生产任务、独立质量记录、独立实际重量、独立最终检验结果、独立包装关系、独立托盘关系、独立装柜关系、独立发货关系、独立安装位置/构件信息。

## P-10 人员 ≠ 角色 ≠ 权限 ≠ 班组（第四轮新增，已确认事实）

- 人员是自然人；角色（如生产主管、质检员、仓管）是职能身份；权限是系统操作许可；**班组是正式生产组织**（一班、二班……）。四者不得混用同一套数据。
- 人员有一个主要所属班组，允许临时借调（沿用 J-14/Q-15）；借调影响"人在哪个班组出勤"，但"构件由哪个班组主责、某道工序由哪个班组实际完成"由 P-11 单独记录，不靠借调关系推断。

## P-11 班组三层关系：主负责班组 / 执行班组 / 实际作业人员（第四轮新增，已确认事实）

一条清晰的责任链：**实际构件 → 主负责班组 → 工序生产任务 → 实际执行班组 → 实际作业人员**。

1. **构件主负责班组（primary team）**：每个实际构件有且仅有一个当前主负责班组（如 GZ1-001-1 = 一班），代表该构件整体生产管理责任（协调、跟进、对外交期责任）。
2. **工序实际执行班组（execute team）**：每道工序的生产任务记录实际由哪个班组完成，**允许与主负责班组不同**。
3. **实际作业人员（worker）**：扫码报工的具体工人，记录到自然人。

帮工规则（已确认）：
- GZ1-001-1 主责一班；下料由三班帮忙、火校由二班帮忙——**构件仍然主责一班，绝不因帮工把构件转给三班/二班**。
- 帮工通过"该工序任务的执行班组=帮工班组"表达，而不是修改构件主责。
- 示例工序归属：组立→一班、焊接→一班、下料→三班、火校→二班、打磨→一班。
- 主负责班组如何指派、能否变更及变更留痕，见 N-15（待确认）。

## P-12 班组统计双口径（第四轮新增，已确认事实）

两种统计必须分开呈现，**严禁混为一谈**：

1. **班组负责构件情况（按主责）**：按"项目→子项目→班组"查看该班组主责的构件：负责构件数量、已完成、生产中、未开始、返工、异常、完成率。
2. **班组实际执行工作量（按执行事实）**：该班组实际完成的工序数量、完成工序数量、实际重量、实际米数、实际件数、实际工时（适用时）；**帮工工作量计入执行班组**（三班帮下料 75 件、帮火校 30 件，归三班），不计入主责班组。

## P-13 生产计划是核心业务，不是事后报表（第四轮新增，已确认事实）

- 核心闭环：**生产计划 → 任务安排 → 班组执行 → 实际报工 → 实时完成情况 → 计划偏差 → 风险预警 → 生产管理人员调整 → 新计划 → 继续执行**。
- 目标：让生产主管**提前**知道哪里可能完不成（周中即可发现），而不是月底才发现。
- 计划层级可下钻：主项目 → 子项目 → 生产计划 → 班组 → 构件 → 工序 → 生产任务 → 生产报工；要能回答"为什么这个计划没完成"，最终定位到项目/子项目/班组/构件/工序/任务/人员/设备/材料/质量中的具体原因。
- V1 不做复杂 APS 自动排程；重点是"能发现影响、能调整、能追溯"。
- 计划粒度（N-13）、周期（N-14）、制定与调整权限（N-12）均**待人工确认**，本节只确认"计划必须作为独立核心业务对象存在"。

## P-14 实时完成口径：六个指标（第四轮新增，已确认事实）

任何计划节点至少同时展示：

| 指标 | 含义 | 例（本周计划 200 件） |
|------|------|----------------------|
| 计划总量 | 该周期计划目标 | 200 |
| 截至当前理论应完成量 | 按计划节奏到"现在"本应完成的量 | 80 |
| 实际完成量 | 报工事实累计 | 62 |
| 当前差额 | 实际 − 应完成（负数为欠账） | −18 |
| 当前完成率（健康度） | 实际 ÷ 应完成 | 77.5% |
| 计划风险状态 | 正常/提前/滞后/严重滞后/暂停等 | 滞后风险 |

- 不允许只显示"62/200"；总进度（实际÷计划总量=31%）可同时显示，但不能替代健康度。
- "应完成量"的计算节奏（按工作日均摊或按里程碑节点）属技术实现，项目组定默认算法；风险阈值（如低于多少算滞后/严重滞后）由业务给初值、系统可配置。
- 预计完成时间是否在 V1 展示见 N-18（待确认）。

## P-15 计划调整必须版本化留痕（第四轮新增，已确认事实）

- 计划**不得无痕覆盖**。例：原计划 9月20日完成 100 件 → 因设备故障调整为 9月22日完成 100 件。
- 每次调整必须保留：原计划（原目标量/原日期）、新计划、调整原因、调整人员、调整时间、完整调整历史。
- 当前只有最新有效计划用于执行；历史计划仅用于追溯与对比。

## P-16 计划偏差状态与原因（第四轮新增，已确认事实）

- 偏差状态至少支持：正常、提前、滞后、严重滞后、暂停（具体名称后续统一）。
- 偏差原因必须可标注：材料影响、设备影响、质量返工影响、人员/班组影响、其他原因；允许一个节点关联多个原因。
- 原因不是自由文本备注，应能反查到具体来源单据（缺料预警单、设备停机事件、返工任务等）。

## P-17 计划 × 材料联动（第四轮新增，已确认事实）

- 联动链：**生产计划 → 材料需求 → 当前库存（含公共余料）→ 已采购在途 → 可生产数量 → 风险提示**。
- 例：下周计划 100 件，库存仅支持 60 件，或材料已采购未到厂 → 计划节点标"材料风险"并提示缺口/在途预计到货。
- 型钢按材质/型号/截面/长度/根数/重量参与测算（沿用 Q-09/Q-13 口径）。
- **本轮不决定**"材料不足是否禁止下达计划"（见 N-16，待老板确认）；V1 至少做到提示风险。

## P-18 计划 × 质量联动（第四轮新增，已确认事实）

- 计划 100 件、生产报工 100 件，其中 10 件终检不合格需返工：**不得显示"100 件全部完成"**。
- 业务链：生产 → 检验 → 不合格 → 缺陷处置 → 返工（新任务 attempt+1）→ 再检 → 最终完成。
- 因此计划完成至少需要两个口径：**生产完成**（工序完工事实）与**质量合格完成**（最终检验合格事实）；返工件不计入合格完成，再检合格后计入。是否在 V1 双率并列展示见 N-17（待确认）。

## P-19 计划 × 设备联动（第四轮新增，已确认事实）

- 关键设备故障时，系统要能串起：**设备异常 → 受影响生产任务 → 受影响构件 → 受影响班组 → 受影响计划节点**。
- V1 不要求自动排程、不要求设备实时采集；重点是登记停机事件并发现影响范围。设备在 V1 的管理深度见 N-19（待确认）。

## P-20 生产管理驾驶舱与下钻（第四轮新增，已确认事实）

老板/生产主管首页必须直接看到：
- 今日：计划、应完成、实际完成、差额；本周：计划、应完成、实际完成、差额。
- 风险清单：计划滞后的主项目、计划滞后的子项目、计划风险班组、材料风险、设备风险、质量返工风险。
- 逐级下钻：主项目 → 子项目 → 班组 → 构件 → 工序 → 生产任务 → 生产报工（与 P-13 一致）。

## P-21 计件工作量按实际执行事实归属（第四轮新增，已确认事实）

- 沿用 J-12/J-13：**生产事实与计价规则分离**；计价规则可配置、历史计价结果保留。
- 班组实际工作量基于"实际完成的生产工序/生产事实"，执行班组是谁，工作量就算谁的：主责一班、下料由三班执行，则该下料工作量归三班。
- **绝不能**按"构件主责班组"把该构件全部工序工作量都算给主责班组。
- 具体单价规则沿用 J-12 配置，本轮不重新设计。

## P-22 图纸/模型与实际构件的绑定预留（"点模型"业务基础，第五轮新增）

- 未来场景：打开 主项目→子项目→CAD/布置图/模型，点击图中 GZ1-001-1，实时看到该件全部状态。**V1 不开发 3D/BIM 浏览与图形引擎**，但必须在业务上存在绑定键：
  - 图纸/模型文件（图号、版次、文件类型[布置图/详图/模型]、页码/视图）；
  - 图中构件定位标识（图元编号，或 轴线/区域+构件号 的稳定组合）↔ 实际构件 ID。
- 绑定方向：**【图纸/模型中的构件对象】→【MES 实际构件】→【实时状态聚合】**。V1 即使没有图形界面，导入清单时也应把图号/版次/图元标识作为构件清单字段落库，否则二期点模型要回头清洗全部历史数据。
- V1 做到哪一步待 **N-20**；图纸由谁提供、图元标识规则待 **N-21**。

## P-23 构件实时状态视图的数据责任（第五轮新增）

点模型/布置图点开一件时要求展示的信息，每一项都必须有唯一事实来源（具体核对见第十五部分）：基本信息（清单+实体）、主/子项目、零件（N-10）、材料与批次（P-24）、当前工序/已完成/未完成（路线+任务+报工）、当前任务、主责班组、执行班组、作业人员、计划完成时间（计划行最新版本）、实际完成时间（报工事实）、计划完成率/是否延期（P-14）、延期原因（P-16/P-29）、质量状态与返工（检验/缺陷/再检）、当前库存位置、托盘、集装箱、发货状态、后续物流状态。
- 结论预判：除"图纸绑定"（C-18）外，其余事实在前四轮规则中均已有归属；"当前工序/当前状态"由系统按任务与报工实时聚合（技术实现，项目组定）。

## P-24 材料双向追溯（第五轮明确为必须能力）

- 正向：材料采购 → 入库（批次/炉批号/质保书）→ 套料/下料 → 零件 → 实际构件。
- 双向查询必须成立：
  1. 某材料批次最终进入了**哪些实际构件**（经哪张套料批次/下料记录）；
  2. 某实际构件的各零件用了**哪些材料批次**、对应哪几张质保书（J-04 的细化落地）。
- 余料回池再利用时，链条跨批次不断裂（余料带来源批次，使用时记新去向）。

## P-25 统一异常/预警（第五轮新增）

- 八类异常必须用**统一异常事件**表达，不允许各模块各报各的、口径不一：
  ①生产延期 ②材料短缺 ③采购延期（到货晚于计划需求日）④设备故障 ⑤质量返工 ⑥仓库异常（账实不符/找不到料/库位冲突等）⑦发货延期 ⑧装柜异常（超重/违规混装/箱容不足）。
- 异常事件要素：类型、等级、来源单据（计划/任务/采购单/停机事件/缺陷单/装箱单等可反查）、主项目、子项目、构件（可空，聚合级异常允许）、发现时间/发现方式（自动/人工）、状态（未处理/处理中/已闭环）、责任人、处理措施与闭环时间。
- 下钻链：异常 → 主项目 → 子项目 → 构件 → 具体原因单据。
- 哪些自动生成、如何通知待 **N-22**。

## P-26 业务纠错：事实不允许删除，走更正/冲销（第五轮新增）

- 生产报工、质检、库存出入等**事实提交后不得物理删除、不得静默修改**。
- 纠错标准路径：原记录保留（标记"已被更正"）→ 纠错申请（错误类型：误扫构件/工序报错/构件报错/数量报错/班组报错/其他）→ 分级审批（**N-23**）→ 生成更正记录（更正前后值、申请人、审批人、时间）或冲销记录（被下游引用时：已质检/已入库/已计价锁定/已发货）→ 全部进审计履历。
- 与 operation_logs 的分工：日志是"谁在何时做了什么操作"的技术审计；更正记录是业务凭据，二者都不能少。

## P-27 主项目/子项目生命周期（第五轮新增；第六轮定稿为八态）

- 【第六轮定稿·N-24 已确认】统一**八态**（不为凑状态而删并）：
  **草稿 → 准备中（清单/图纸/基础数据导入）→ 生产中 → 暂停 → 生产完成 → 发货中 → 已完工 → 关闭（只读）**。
  - 草稿：项目已建档、基础数据未齐；准备中：导入阶段；生产中：存在在制任务；暂停：整体挂起（需原因）；生产完成：全部构件终检合格、未全部发货；发货中：已有发运确认、未全部发完；已完工：全部构件发货完成；关闭：财务/资料收尾后冻结只读。
- 状态变化必须保留历史；**关闭需管理权限；重新打开需权限+原因**。
- 状态推进采用"系统按事实建议 + 有权人确认"；子项目状态独立，主项目状态由子项目汇总（沿用 P-3）。

## P-28 图纸版本与技术变更（V1 简版边界，第五轮新增）

- 图纸**必须有版次**，不允许系统中只有一个无版本图纸文件。
- V1 简版变更记录至少包含：图号、旧版→新版、变更时间、变更人/变更来源（客户/设计/工艺）、变更原因、**受影响构件清单**（系统按构件清单记录自动列出：哪些未生产/在制/已完工/已发货）、处置结论（继续使用/返工/报废，人工判定后登记）。
- V1 不做完整 ECN/会签流；变更发生后已生产构件的处置必须有地方登记并可触发返工任务。管理深度待 **N-25**。

## P-29 生产任务暂停 / 取消（第五轮新增）

- 任务除 待开始/进行中/完成 外，必须支持**暂停**与**取消**两个事件：
  - 暂停：必填原因分类（待料/设备/质量/图纸变更/人员/其他）、暂停开始时间、恢复时间、暂停时长；
  - 取消：必填原因、审批人；取消后该件该道工序是否重新生成任务（如改路线）必须可查。
- 暂停/取消均影响计划：作为偏差原因来源（P-16），但是否调整计划仍走 P-15 版本流程，不由暂停自动改计划。
- 【第六轮定稿·N-26 已确认】班组/执行人员可发起暂停（必填原因）；生产主管确认暂停/恢复；取消需主管权限；不自动改计划。

## P-30 权限模型与事实保护（第五轮新增；第六轮定稿）

- 【第六轮定稿·N-27 已确认】**角色不写死为数据库结构**：系统按"角色 + 功能权限 + 操作权限 + 数据范围"设计；当前 11 类角色（老板、管理层、生产主管、班组长、工人、技术、质检、仓库、采购、设备、财务）只是公司当前管理制度的初始数据，**未来允许增删角色**。
- 操作权限分五类：**查看 / 执行（操作）/ 修改 / 审核 / 管理**。
- **数据范围**可按：公司 / 主项目 / 子项目 / 班组 / 个人负责范围 控制。
- 人员-角色-权限 与 人员-班组 是两套关系（P-10）；同一人可持多角色。
- 硬性原则：
  1. 普通工人只能扫码报工/查看本人相关信息，不能修改生产事实、不能删除任何历史；
  2. 事实更正统一走 P-26，**管理员也不能直接覆盖原始业务事实**；
  3. 价格/结算、质检判定、入库过磅等互斥职责不授予同一执行岗（最小权限+职责分离）。
- 初始角色清单与矩阵由项目组起草、各部门会签、老板批准后作为系统初始配置（内容可在系统中维护，不硬编码）。

## P-31 统一异常原因分类（第六轮定稿）

- 【第六轮新增·已确认】全公司统一原因分类，用于计划延期、任务暂停、质量异常、设备异常、材料异常等所有需要登记原因的场合，避免自由填写"其他"：
  **①材料 ②设备 ③技术/图纸 ④生产组织 ⑤质量 ⑥物流 ⑦其他**（"其他"必填具体说明）。
- 三个概念严格分离：**异常（发生了什么事）≠ 异常原因（为什么发生，取上述七类）≠ 责任/受影响班组（影响到谁）**。
  例：设备故障导致 3 班任务受影响——原因=设备，受影响班组=3 班，不得把"3 班"记成原因。

## P-32 实际构件（actual_component）是 MES 核心数字实体（第六轮定稿）

- 【第六轮新增·已确认】GZ1-001-1 这样的实际构件是系统的核心数字实体，数据库设计阶段围绕它建立完整关系。一个实际构件可关联（随业务阶段逐步挂接）：
  主项目、子项目、构件清单记录、图纸/版次/工程对象标识、零件实例、材料批次、套料批次、下料记录、生产计划行、生产任务、主责班组、执行班组、作业人员、设备、质量记录/返修、理论/实际重量、库存位置、托盘、集装箱、发货、运输、现场安装位置、二维码。
- 所有关联都不得破坏"一件一实体、一件一履历"原则；实时状态由该实体的业务数据聚合，不在外部模型系统中重复维护。

# 第四部分 冲突清单（按要求五要素列出；已解决项保留原文并加状态）

## C-1【设计冲突】现有项目表是单层，无法表达主/子项目

【冲突问题】主项目→子项目两层管理在数据里没有承载结构。
【原规则】V1.1/review：projects 单层；构件直接 project_id 到项目。
【新规则】P-1/P-2：主项目下必须有可独立管理、独立统计的子项目版块。
【为什么冲突】单层 projects 无法支持"按子项目独立看板 + 主项目汇总"；把子项目做成普通字段/分类不满足"独立管理版块"要求。
【建议处理方式】projects 保留为**主项目**，新增 **subprojects（子项目）**（id、主项目_id、子项目编码、名称、类型[厂房/办公楼/设备区/结构分区…字典]、状态、计划/实际日期、独立统计入口）；不建议同表自引用；子项目 NOT NULL FK 主项目。
【第三轮状态】**N-1 已确认**：采用主项目+子项目两层；可写入正式 V1.2 设计（本轮仍只改本文档）。

## C-2【归属冲突】构件、零件、图纸、工艺实例到底挂哪一级

【冲突问题】原设计所有业务表 FK 指向单层 projects。
【原规则】components/component_items/parts/drawings/路线实例等 project_id → projects。
【新规则】P-4/P-8：构件清单记录、实际构件、零件直接归属子项目，主项目上溯。
【为什么冲突】挂主项目则子项目独立清单/进度无法落地。
【建议处理方式】构件清单记录、实际构件、零件、构件级图纸、构件工艺实例、任务、质检、成品库存、托盘/箱装载明细、发运明细 **一律挂 subproject_id（NOT NULL）**；主项目 id 仅作报表冗余（由子项目带出）；项目级图纸、采购、主项目汇总报表挂主项目。
【第三轮状态】归属规则随 P-4/P-8 **已确认**；零件到件的具体建模方式另见 N-10。

## C-3【编号冲突】构件号（component_no）的唯一性范围 —— ✅已关闭

【冲突问题】构件号在哪个范围内唯一，原建议 (project_id, component_no)。
【原规则】Q-01：构件号在"项目内"唯一。
【新规则】跨子项目允许相同构件号（第三轮事实四）；同一子项目内同号同名为一行数量。
【为什么冲突】主项目范围内唯一会导致不同子项目同号无法导入。
【建议处理方式】构件清单记录在**子项目内唯一 UNIQUE(subproject_id, component_no)**；主项目层面显示"子项目+构件号"区分。
【第三轮状态】**老板已确认跨子项目可同号（N-2 关闭）**，按子项目内唯一执行；同一子项目内是否允许两行同构件号（不同版次等）另见 N-11。

## C-15【责任口径冲突·第四轮新增】构件主负责班组与工序执行班组未分离

## C-16【数量语义冲突·第四轮新增】计划/任务/报工/质检/包装/发运可能重新引入"实际构件数量>1"

【冲突问题】第三轮已确认"数量只属于构件清单记录，实际构件一件一实体"；但计划目标量、批量报工、一次装多件等场景容易在实际构件级行上重新塞数量字段。

【状态】规则已确认，正式设计稿必须逐表遵守。

  - **A（推荐）**：计划滞后（健康率破阈值）、材料缺口、采购逾期（承诺到货日>计划需求日）、设备停机登记后、终检不合格发生、发货日临近而未齐套 —— **系统自动生成异常**；仓库异常、装柜异常由人工登记；V1 通知仅用**系统内消息/驾驶舱红点**，不做短信微信。
  - B：异常全部人工登记。
  - C：自动生成 + 手机推送/短信（增加成本与打扰）。
- **影响**：决定后台计算任务与消息模块范围；阈值沿用项目组可配置初值。
- **当前状态**：**待人工确认（老板/生产主管）。**

#### N-23 业务纠错的审批分级

  - B：所有更正统一由生产主管一人审批。
  - C：班组长可自行更正当日记录、无需审批（仅留日志）。
- **影响**：决定审批流配置与冲销联动范围；选 C 与 P-30 事实保护原则冲突。

# 第九部分 生产计划与班组协作业务模型（第四轮新增详解）

## 9.1 计划业务模型（计划 ≠ 报表）

1. **计划对象**：生产计划头（主项目/子项目、周期类型[年/月/周/日]、时间范围、编制人、状态[草稿/已下达/调整中/已关闭]）+ 计划行（粒度按 N-13：推荐"构件+工序"；目标量；计划起止/节奏）。
2. **任务关系**：工艺路线为每个实际构件生成工序任务（沿用既有路线结论）；计划行与任务关联——计划管"应该什么时候完成多少"，任务管"具体哪件哪道工序派给谁做"，报工管"实际谁在什么时间做成了什么"。三者严格分离：**计划可调整而不篡改任务/报工事实；报工事实永不被计划调整覆盖**。
3. **实时六指标**（P-14）：计划总量、截至当前应完成、实际完成、差额、健康完成率、风险状态；总进度另列。
4. **班组维度计划**：周计划可按班组切目标（本周 一班50/二班70/三班40/四班40），实时对比实际——注意该对比用"执行工作量口径"还是"负责构件口径"由页面明确标注，默认风险卡片以执行口径为准（谁在干活谁有风险），负责口径另页查看。
5. **调整**（P-15）：当前仅最新版本生效；每次调整生成版本记录（原目标/原日期、新目标/新日期、原因分类、调整人、时间、审批记录）。
6. **偏差原因**（P-16）：材料/设备/质量返工/人员班组/其他，可多原因并关联来源单据。
7. **权限**：N-12 待确认（推荐：计划员/主管编、下达；主管调整留痕；交期级老板审批；班组只执行反馈）。

## 9.2 帮工业务模型

- 帮工的唯一表达方式：**该工序任务的执行班组 ≠ 构件主负责班组**；不新增"帮工单"也能表达，是否另做帮工协调记录属技术实现。
- 不变量（系统校验建议）：
  1. 任一时刻一个实际构件只有一个当前主责班组；
  2. 一道工序任务只有一个执行班组（多人共同作业时，人员可多个，班组以任务执行班组为准）；
  3. 修改执行班组不改变主责；主责变更不改写历史执行记录；
  4. 计件试算取执行班组（P-21）。

## 9.3 驾驶舱（P-20）

- 卡片：今日（计划/应完成/实际/差额/状态）、本周（同）。
- 风险榜：滞后主项目、滞后子项目、风险班组、材料风险、设备风险、质量返工风险。
- 下钻终点必须能落到"哪个任务、哪个人、哪台设备、哪批料、哪张缺陷单"。

# 第十部分 数量语义专项审查（C-16 落地表）

> 原则：实际构件级业务"一件一行"；件数 = COUNT(行数)；重量/长度/工时等是工序度量，独立字段；"数量>1"只允许出现在构件清单记录、计划行目标、物料（材料批次）侧。
>
> 【第六轮定稿】全文数量语义统一为七类，严禁混用：
> **①构件清单数量**（清单行 quantity，可>1）｜**②实际构件数量**（永远=实体个数，一件一行，无 quantity 字段）｜**③零件需求数量**（BOM 模板×清单数量算出的需求）｜**④实际生产数量**（报工/任务到件行数，外加重量/长度/工时等度量）｜**⑤材料数量**（重量/长度/根数/张数，物料计量）｜**⑥包装数量**（托盘装载构件数=COUNT）｜**⑦发货数量**（发运明细到件行数/快照件数=COUNT）。
> 3 件 GZ1-001 必须产生 3 个实际构件实体（GZ1-001-1/-2/-3），禁止用一个实际构件的 quantity 表达多件。

| 业务对象 | 记录形态 | "数量"如何表达 | 审查结论 |
|----------|----------|----------------|----------|
| 构件清单记录 | 一构件号一行 | 计划数量 quantity（可>1） | ✅ 唯一合法的多件数量 |
| 实际构件 | 一件一行 | 无数量字段（隐含 1） | ✅ 已确认 |
| 零件 | 第六轮 N-10 定稿：构件级 BOM 模板共性定义，实际构件下挂零件实例到件 | 零件实例行不设倍数值 | ✅ 已定稿（模板+实例） |
| 材料需求 | 按物料汇总 | 重量/长度/根数/张数（度量值，非构件件数） | ✅ 物料度量 |

# 第二十部分 第六轮：V1.2 最终收口与业务冻结候选输出

> 本部分吸收第一~五轮全部结果，统一业务规则、消除冲突、压缩待确认事项、明确 V1 四层边界。

## 一、已确认业务规则（第六轮收口后的定稿清单）

**A. 组织与项目结构（前五轮已确认，继续有效）**

1. 主项目 → 子项目两层结构：子项目是独立业务管理单元（构件/零件/材料/套料/下料/生产/质量/成品/包装/集装箱/发货/进度各自独立可查），主项目负责汇总并可逐级下钻（N-1、P-1~P-3）。
2. 跨子项目允许相同构件号并存；实际构件编号统一"构件号-序号"（GZ1-001-1），数量 1 也生成 -1；唯一键=子项目+构件号+序号；报废不重用、补件续号；二维码全局唯一（N-2、N-3、P-4）。
3. 项目生命周期**八态**：草稿/准备中/生产中/暂停/生产完成/发货中/已完工/关闭；状态变化留历史；关闭需管理权限；重开需权限+原因（N-24、P-27）。

**B. 构件清单 → 实际构件 → 零件（第六轮定稿）**

4. 业务链定稿：**构件清单 → 构件级零件/BOM 模板 → 实际构件 → 零件实例**；模板负责共性定义，零件实例负责到件生产追踪（N-10 选 A）。
5. 同一子项目同一 component_no 原则上仅一条构件清单记录，多件用清单 quantity 表达；清单数量 3 必须生成 3 个实际构件实体（N-11、P-7）。
6. 实际构件一件一实体、一件一履历，本身无 quantity>1 语义（P-8/P-9）。
7. 全文数量语义统一为七类：构件清单数量/实际构件数量/零件需求数量/实际生产数量/材料数量/包装数量/发货数量（第十部分，第六轮加注）。
8. 实际构件（actual_component）是 MES 核心数字实体，围绕它建立全部业务关系（**P-32**）。

**C. 材料与套料（前五轮已确认，继续有效）**

9. 业务链：采购→到货→供应商重量→本厂过磅→材料批次（炉批号）→材质证明（质保书）→库存→套料→零件→实际构件；支持反向追溯 实际构件→零件→套料→材料批次；余料必须可追溯来源与去向（J-04、P-24）。
10. 套料采用"专业套料软件 → Excel/CSV 导入 → MES 套料批次 → 零件 → 实际下料 → 实际材料消耗 → 余料"模式；MES 不做专业几何套料（P-20~P-21）。

**D. 计划/任务/报工（第四轮已建，第六轮关键项定稿）**

11. 三者严格分离：生产计划回答"生产什么、何时完成"；生产任务回答"哪个实际构件、哪道工序、安排给谁"；报工回答"实际谁、何时完成了什么"（P-11~P-13）。
12. 计划周期月→周→日；计划最低业务颗粒度=**子项目+实际构件+工序**；班组属于任务执行层，不进计划核心粒度（N-13、N-14）。
13. 实时计算七指标：计划总量、理论应完成量、实际完成量、计划偏差、实际/理论完成率、总体完成率、风险状态；下钻链 主项目→子项目→计划→构件→工序→任务→班组→人员（P-13/P-17）。
14. 计划不能被实际数据覆盖；计划调整必须版本留痕：原计划、新计划、调整原因、调整人、调整时间、审批信息（P-15）。

**E. 班组与人员（第六轮定稿核心口径）**

15. 三个班组概念分离：实际构件→主责班组；生产任务→执行班组；生产报工→实际执行人员；协作班组干活不改变构件主责班组（N-15 核心原则、P-10/P-12）。
16. 统计双口径：主责构件责任范围 vs 实际执行工作量；未来计件/班组结算以实际执行工作量为基础（P-12）。
17. 任务暂停/取消：班组/执行人可发起暂停并填原因；生产主管确认暂停/恢复；取消需主管权限；暂停/取消不自动修改计划，计划变化独立走调整流程（N-26、P-29）。

**F. 质量（第六轮定稿）**

18. 生产完成 ≠ 质量合格；质量过程状态统一为：**生产完成/待检/一次合格/不合格/返修/复检/最终合格**；例：生产完成 100、一次合格 92、返修 8、最终合格 100（N-17、P-18）。
19. 驾驶舱同时展示生产完成与最终合格（双率并列）。

**G. 设备（第六轮定稿）**

20. V1 做：设备台账、设备状态、开停机、故障、维修，以及 设备→任务→构件→班组→计划 的影响追踪；不做复杂 APS（N-19、P-19）。

**H. 图纸/工程变更/数字映射（第六轮定稿）**

21. V1 支持基础工程变更：图纸→版次→变更记录→受影响构件→受影响零件→当前生产状态→技术处置；历史版本必须保留；不做完整 PLM（N-25、P-28）。
22. V1 只保存：外部工程对象标识 + 图纸 + 图纸版本 + 实际构件 ID；不绑定某一个具体软件；不开发 3D/BIM 查看器；未来 CAD/BIM/模型点击构件查询 MES 实时状态时，状态以 MES 业务数据为准、不在模型系统重复维护（N-20、N-21、P-22/P-23）。

**I. 异常中心与原因分类（第六轮定稿）**

23. 一期自动发现：计划落后/任务逾期、材料不足风险、设备故障影响、质量不合格/返修、图纸变更影响生产，以及其他明确业务异常；异常至少关联：来源、对象、影响构件、影响工序、影响计划、影响班组、原因分类、处理人、处理状态、关闭信息（N-22、P-25）。
24. 统一原因分类七类（**P-31**）：材料/设备/技术图纸/生产组织/质量/物流/其他；异常≠异常原因≠责任班组（设备故障影响 3 班，原因是设备、不是 3 班）。

**J. 事实保护与权限（第六轮定稿）**

25. 原始业务事实不可静默覆盖：错误报工/重量/数量/班组一律走 原始事实→更正申请→原因→审核→更正结果→历史记录；**管理员也不能直接覆盖原始事实**（N-23、P-26）。
26. 权限模型：角色+功能权限+操作权限+数据范围；当前 11 个角色只是初始管理制度、不写死成库结构，未来可增删角色；操作权限五类=查看/执行/修改/审核/管理；数据范围=公司/主项目/子项目/班组/个人（N-27、P-30）。

**K. 包装/发运（前五轮已确认，继续有效）**

27. 托盘：一个主项目内允许多个子项目混装；集装箱默认属于一个主项目、可含多个子项目和多个托盘；不同主项目原则上不混装；跨主项目混装必须授权+原因+完整历史（P-5）。
28. 托盘支持装入/拆出/重新包装；集装箱支持装柜/卸柜/重新装载/重复使用；历史事实不可覆盖；发货确认形成实际装运快照（P-5/P-6）。

**L. 管理驾驶舱**

29. 管理层重点看到：项目进度、计划达成、生产完成、最终合格、材料风险、设备风险、质量异常、计划延期、包装/集装箱、发货、物流、重大异常；支持逐级下钻；核心是回答"为什么落后"——计划落后→差异→原因→影响构件/工序/班组→材料/设备/质量归因→处理（P-17）。
