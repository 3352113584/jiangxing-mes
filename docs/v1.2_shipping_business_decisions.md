## 一、业务目标（用户 2026-09-19 确认，12 条）

1. 构件装托后，自动进入发运清单；
2. 发运清单不是人工维护表，由真实业务事实实时推导；
3. 发运员以"托盘"为发运操作单位；
4. 发运员可选择托盘加入一个发运/集装箱草稿；
5. 确认发运后，该托盘内所有 actual_component 形成已发货事实；
6. 构件始终可反查：项目 → 子项目 → 构件 → 托盘 → 柜号 → 柜型 → 发运记录；
7. 集装箱可反查：柜号 → 柜型 → 发运状态 → 所有托盘 → 所有构件；
8. 同一主项目不同子项目允许混托；
9. 不同主项目混托必须 mixed_load_authorization 授权；
10. 不要求发货员逐个构件点击发货；
11. 发运确认以整托为单位原子完成；
12. "加入发运草稿"与"确认已发货"是两个不同阶段。

## 三、最终裁决记录（2026-09-19）

| 裁决 | 结论 |
|---|---|
| Q5 发运操作粒度 | **A** — 托盘为发运操作单位；`ship.shipment_pallet` 为正式业务实体；发运清单不建业务表 |
| Q6 封条 | **不实施** — `container_seal` 第一阶段不建（不建表、不加列）；不因封条增加任何发运前置条件 |
| Q7 shipment.container_id | **nullable** — 兼容散运/裸件；一箱可关联多个 shipment；不建唯一约束 |

| Q9 发运质量前置 | **仅 RED-09**（final_qualification 有效事实）；暂不以 production_completed/painting 为发运前置；production_completed 仍按 E-2 由 painting 完成驱动 |

## 四、推荐最终模型（冻结）

```
actual_component ──pallet_load(is_current)── pallet ──container_load(is_current)── shipping_container
                        │                      │                                        │
                        │                      └── shipment_pallet(is_current, 新) ── shipment ──┘
                        │                                        │                   (container_id, 新列, nullable)
                        └────────────── shipment_snapshot（确认时构件级冻结，T-1 保护）──────┘
```

**三层事实分离**：

| 层 | 表 | 语义 |
|---|---|---|
| 装载事实 | pallet_load / container_load | 当前态（is_current），承载"构件在哪个托、托在哪个箱" |
| 操作事实 | shipment_pallet（新） | 托盘级发运归属：草稿加入 → 确认冻结，两阶段承载（目标 12） |
| 归属快照 | shipment_snapshot | 确认时刻构件级冻结副本（项目/子项目/托盘号/柜号/重量/QR），T-1 保护 |

**反查链验证**（目标 6/7）：

- 构件 → 项目/子项目（actual_component→subproject→main_project）→ 托盘（pallet_load.is_current）→ 柜号/柜型（container_load.is_current → shipping_container）→ 发运记录（shipment_pallet → shipment）✅
- 集装箱 → 柜号/柜型（本表）→ 发运状态/时间（shipment.container_id 反查）→ 所有托盘（container_load）→ 所有构件（pallet_load）✅
- 发货后托盘号不丢失：shipment_snapshot.pallet_no_snapshot / container_no_snapshot 冻结副本。

**混托归属规则**：shipment_pallet = 操作事实（整托随单）；shipment_snapshot = 归属事实（构件级，可跨主项目）；shipment.main_project_id 仅表示发运单主项目，混托构件归属以 snapshot 为准。跨主项目混托仍须 mixed_load_authorization。

## 六、退运释放流程（目标 J 的正式流程）

```
shipment(confirmed/in_transit/delivered) → shipment_event('return')
  → 单事务：
     ① shipment.status → returned
     ② shipment_pallet(is_current=true) 行置 is_current=false（历史保留）
     ③ pallet_load_history 写 remove 事件（含 operator）
     ④ pallet_load(is_current) 行置 false；pallet.status → empty（托盘复用）
     ⑤ 构件缓存位同步回退：shipped → in_stock
  → 补发 = 新 shipment 行（reship 语义）；构件重新装托须重走装托校验
```

缓存位回退说明：与 Q1=A 不冲突——Q1 约束的是 `quality_status`（质量域）不因 revoke 回退；本流程回退的是 `production_status` 物流段**缓存位**，其唯一职责就是跟随事实（R-SH-0.2），事实变化缓存位必须同步。
