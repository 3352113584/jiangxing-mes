# V1.2 Phase 2 数据库设计计划（Phase 2 Database Design Plan）

> 生成时间：2026-09-18 ｜ 前置：Phase 1 FROZEN（`docs/v1.2_phase1_freeze.md`，PHASE_2_READY=YES）

> 范围边界：仅 Domain Model → PostgreSQL 物理设计；前后端 / API / Android / Vue / Docker **不在本轮**。
> 上位约束：`docs/v1.2_database_domain_model.md`（FROZEN，第 13 节十项不变量必须全部继承）。

## 1. PostgreSQL 版本

**PostgreSQL 16**（运行环境：容器 `mes-postgres-dev`，库 `jiangxing_mes`，业务表当前 = 0，从零建表）。
选择理由：当前稳定大版本，覆盖本计划全部所需特性（partial unique index、ENUM ALTER ADD VALUE、identity 列、行级锁语义）；16 系列维护期内无需跨版本风险。

## 2. Schema 划分

倾向方案：**单库多 schema，按域划分**（与模型 3.x 域一一对应，便于权限切分与只追加权限回收）：

| Schema | 域 | 代表表 |
|---|---|---|
| ref | 字典/配置/编号规则 | operation_type、component_type_dict、import_field_mapping、code_rule、单位字典 |
| md | 主数据 | material、supplier、employee、team、warehouse/storage_location |
| eng | 工程定义 | component_list_item、bom_template(_line)、route_template(_step)、drawing_revision |
| imp | 导入过程域 | component_list_import_batch、import_row、import_correction_result、nesting_import_batch |
| prod | 计划/任务/报工/质量 | plan(_version/_line)、production_task、production_report、inspection、component_scrap_record |
| whs | 采购/库存/仓库 | purchase_order(_item/_receipt)、stock_balance/ledger、material_issue_document/line、material_reservation、surplus_material、scrap_record |
| ship | 包装/发运 | pallet、shipping_container、shipment_snapshot |
| aud | 事件/快照/留痕 | 各类 event 行、plan_progress_snapshot、report_snapshot |

备选方案：单 schema public + 表名域前缀（实现更简单，权限粒度粗）。
**详设评审时二选一定稿**；本文档不强制。

## 3. 表生成顺序（Migration 分批依据）

按依赖层次从零依赖到强依赖：

1. ref 字典与编号规则（code_rule 先行——issue_no/material_code/reservation_no 依赖发号）
2. md 主数据（material → supplier → employee/team → warehouse）
3. eng 工程定义（清单 → BOM 模板 → 路线模板）
4. imp 导入域（import_batch → import_row）——构件清单导入先于实例化
5. 构件/零件实例（actual_component → part_instance，含 lineage 自引用）
6. 采购/到货（purchase_order → receipt/receipt_item → material_batch/certificate）
7. 库存（stock_balance/ledger → issue_document/line → material_reservation → surplus/scrap）
8. 生产（plan → task → report → 质量/报废/返工链）
9. ship 发运（pallet → container → shipment_snapshot）
10. aud 快照/事件类（最后，引用前序全部）

## 4. 主键策略

- 全部实体使用**代理主键**：`BIGINT GENERATED ALWAYS AS IDENTITY`（单体应用、无多写节点，不引入 UUID 随机写放大）；
- 业务码（material_code、issue_no、qr_code、reservation_no 等）一律作 **UNIQUE 非主键**列，与代理键分离（G-2 双层身份结构）；
- 事件/流水表：代理键 + (主体, occurred_at) 组合索引；不加业务主键（事实行天然唯一）。

## 5. 外键策略

- 全部实体间引用**强制 FK**，`ON DELETE RESTRICT`（对应模型第 11 章"事实行禁止删除"——DB 层兜底）；
- **软引用（对象类型+ID，受控取值）不加 FK**：CHECK (ref_type ∈ 受控值域 AND ref_id 非空 或 双空) + 服务层取值校验（决策点①维持）；
- 自引用 lineage（actual_component.replacement_for、part_instance.replacement_of、surplus_material.parent_surplus_id、import_row.corrected_from_row_id）：FK + RESTRICT，禁止 CASCADE；
- 跨 schema FK 允许（同库）。

## 6. 唯一约束

- 继承模型第 5 章唯一性表**逐条落地**（全部 ★ 身份实体），含本次整改新增 4 项：material(material_code 全局)、import_row((import_batch_id, source_identity) 批次内)、material_issue_document(issue_no)、material_reservation(reservation_no)；
- "当前值唯一"（如主责班组当前指派唯一、当前装载唯一）用 **partial unique index**（WHERE 有效态）实现；
- 冗余快照列（origin_part_no 等）明确**不参与**唯一约束（RED-02 结论）。

## 7. CHECK 约束

- 枚举值域：make_type、line_status/step_status、result_status、import_kind、预留状态等 → DB 层 CHECK（或 ENUM，见第 9 节）；
- 条件非空：约束 27（outsource ⇒ supplier_id 非空；inhouse ⇒ 必空）→ CHECK 落地；
- parent≠self：约束 26 → `CHECK (id <> parent_id)`；循环禁止由服务层递归校验（约束 26 S 层）；
- 12 章末"核心事实键 NOT NULL 清单"（occurred_at/recorded_at/操作人/源单外键）逐表落地。

## 8. 索引策略

- **全部 FK 列建索引**（PostgreSQL 不自动创建）；
- 模型第 16 章索引清单逐条落地；
- 只追加事实表：(主体 FK, occurred_at) 复合索引；软引用：(ref_type, ref_id)；
- 允许详设/压测后**增补**索引；禁止删除支撑唯一性/幂等的索引；
- 高频聚合（七指标）依赖快照表而非实时大查询，不为报表滥建索引。

## 9. 枚举/字典策略

| 类型 | 策略 |
|---|---|
| 封闭短枚举（状态机值、make_type、result_status、import_kind 等） | PostgreSQL **ENUM**（ALTER ADD VALUE 增值）或 CHECK——详设按变更频率定，倾向状态机用 ENUM |
| 开放字典（operation_type、management_class、component_type/feature、计量单位） | **字典表 + FK**（ref schema），支持业务自扩 |
| 受控软引用取值 | CHECK (ref_type ∈ …) + 服务层校验，前端禁止自由字符串 |
| **N-2 落点** | receipt_item 验收结论建**受控值域**（字典或 CHECK：合格/待处理/拒收/让步接收…），禁止自由文本 |
| **N-1 落点** | material_code：UNIQUE + 稳定（变更仅走主数据流程）+ 不复用（唯一约束防并行复用；停用码不回收）+ 历史事实经 material 代理键关联 |

## 10. 事务边界

- **状态迁移**：读当前状态 → 校验迁移合法 → 写新状态 + 事件行，**同一事务**（模型 14.2.3）；
- **过账**：stock_ledger 行 + stock_balance 变更同事务（单一扣减依据=material_consumption，RED-04）；
- **导入**：批次/行批量落库；行级校验失败落 result_status=failed 不回滚整批（OPEN-1 默认 B 语义）；
- **实例化**：构件实例 + 零件实例展开同事务（RED-01 数量展开原子性）；
- **发运确认**：快照冻结 + 范围锁定同事务（不变量 8）。

## 11. 并发控制

- A 类聚合根（actual_component 当前状态、production_task、pallet、shipping_container、equipment 等）**行版本号乐观锁**（模型 14.2.1）；后提交版本不符 → 重读重判，禁止静默覆盖；
- 关键互斥（14.2.2 逐条落地）：同构件双托盘互斥（当前装载唯一 + 事务内锁构件）；装柜/拆出锁托盘聚合根；发运确认锁发运范围；超重校验在装载事务内聚合；
- 隔离级别默认 READ COMMITTED + 显式 `FOR UPDATE` 于关键序列化点；不全局 SERIALIZABLE；
- 计划版本 vs 在途报工：按 occurred_at 与版本生效时间口径归属（服务层，口径文档化）。

## 12. 幂等策略

- **client_token 唯一登记**：提交类操作重试返回首次结果，不产生第二条事实（14.1 机制 1/2）；
- **业务防重键兜底**（14.1 机制 3 逐条）：报工、装载、检验 (构件,类型,attempt)、发运确认、**导入行 (import_batch_id, source_identity)**；
- **source_identity ≠ row_number** 结构化执行（约束 29）；content_fingerprint 仅判内容变化；
- 网络/终端超时：同一幂等键重试，禁止新建提交。

## 13. 审计/历史数据策略

- B 类事实/事件表**只追加**：回收 UPDATE/DELETE 权限（约束 24 同款 DB 手段）；
- A 类当前值表：关键主数据与配置变更留痕（历史表或事件行）；停用式演进 = deprecated 标记 + 新行，不物理改写；
- 全表标配审计列：created_by / created_at / occurred_at / recorded_at（可补录必须有值）；
- 批次链（import_batch.supersedes_batch_id）、纠正链（corrected_from_row_id）、lineage 链：永久保留，物理删除禁止。

## 14. Migration 策略

- 工具：**Alembic**（Python 后端既定栈，第三阶段执行）；
- 按第 3 节顺序**一域一批 revision**，可 downgrade 至上一批次；首版全量基线 revision + 后续增量；
- 种子数据：ref 字典初始值（OPEN-2 类型映射初值待业务确认后 seed；code_rule 编号规则）；
- 迁移纪律：Migration 文件不手改已应用版本；结构变更=新 revision；与详设文档同步评审。

## 15. 测试策略

- **场景 A~J 转为 DB 级验收用例**（整改报告第 10 节逐项）：需求恒等/报废补件/返工计数/守恒分解/余料链/make_type 三工序/导入重放幂等/单据行/车次批次——每条含断言（数量不膨胀、无重复实体、约束拦截）；
- 每批 Migration 后必测：唯一约束冲突用例、幂等重放用例（同 client_token/同 source_identity）、状态机非法迁移拦截用例、N-1/N-2 值域用例；
- 数据校验脚本：RED-05 守恒（±容差）、导入重放对账（kept/updated/created 行数核对）；
- 详设评审通过标准：本计划 15 节全部落地 + 场景用例全绿 + 十项不变量逐条核对通过。
