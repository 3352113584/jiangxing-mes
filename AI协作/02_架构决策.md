# 02 架构决策记录（已冻结，未经确认不得更改）

> 依据：第六轮业务冻结 Part 20 + 第一阶段领域模型 v1.2_database_domain_model.md

## AD-01 核心数字实体

**actual_component（实际构件）是唯一核心数字实体。**
- 一件一实体，数量永远隐含为 1，**禁止设置 quantity 字段**。
- 清单 quantity=3 → 生成 GZ1-001-1 / -2 / -3 三个实体；quantity=1 也生成 -1。

## AD-02 唯一性体系

- actual_component 唯一键：`(subproject_id, component_no, instance_sequence)`，子项目内唯一。
- 同一子项目同一 component_no 仅一条构件清单记录（N-11 已确认）。
- QR 码全局唯一，与构件 1:1 终身绑定，报废不复用。
- 报废序号不重用、补件续新序号。
- 内部代理键与业务编号完全分离。

## AD-03 三大分离

1. **计划 / 任务 / 报工** 分表：计划=做什么何时做做多少（版本化，粒度=子项目+实际构件+工序，月/周/日）；任务=哪件哪工序给哪个执行班组（一个任务一个执行班组+多参与人）；报工=实际谁何时做了什么（事实，不回写计划）。
2. **主责班组 / 执行班组 / 实际人员** 分离：主责挂构件（变更留史）、执行挂任务、人员挂报工；协作班组不改变主责；计件以执行事实为基础。
3. **生产完成 / 质量合格** 分离：双状态机独立；质量七态（生产完成/待检/一次合格/不合格/返修/复检/最终合格）；检验以 (构件, 检验类型, attempt) 只追加，返工 attempt+1 不覆盖原检验。

## AD-04 数据四分类

所有实体归入：A 当前状态 / B 历史事实（只追加）/ C 配置字典 / D 业务事件。禁止万能历史表、禁止万能状态表。

## AD-05 事实保护与更正机制

- 原始业务事实不可静默覆盖，**管理员也不能直接 UPDATE 覆盖**（N-23 原则已确认）。
- 路径：原始事实 → 更正申请 → 原因 → 审核 → 更正结果/冲正 → 完整历史。
- 被下游引用的事实更正必须生成冲正记录。

## AD-06 材料双向追溯闭环

`材料批次 → 套料明细 → 零件实例 → 实际构件` 正反向同链；余料带来源/去向；质保书挂批次；13 种重量语义按业务含义分列（事实/计算/快照）。

## AD-07 包装 / 装载 / 发运历史不可变

- 当前装载表 + 事件历史表双轨；装载明细以 actual_component 为粒度。
- 超重服务层事务内硬拦截。
- 发运确认生成**冻结快照**（逐构件冗余值），之后无更新路径。
- 跨主项目混装：授权 + 原因 + 完整历史（mixed_load_authorization）。

## AD-08 权限模型

RBAC（角色可扩展，初始 11 角色仅为配置数据）+ 五类操作权限（查看/执行/修改/审核/管理）+ 五档数据范围（公司/主项目/子项目/班组/个人）；服务端强校验 + 行级过滤 + 职责分离。

## AD-09 时间体系

occurred_at（业务发生时间）≠ recorded_at（录入时间）≠ created/updated（系统审计）≠ 审批时间。事实行双时间必填。

## AD-10 幂等与并发

扫码等 8 类提交操作：client_token 幂等键唯一约束 + 业务防重唯一键双层；聚合根乐观版本 + 装载唯一约束 + 事务内锁定。14 个事务边界已划定（不搞超级事务）。

## 待审查确认的 3 个非阻塞决策点

1. "对象类型 + ID"软引用（更正/审批/异常来源/日志）需受控取值表，防万能化。
2. 余料与材料批次：同表多态 vs 独立表+统一库存标识。
3. 返工任务在七指标中的计件去重口径（按构件工序最终结果计一次）。
