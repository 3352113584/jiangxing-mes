# 00 项目总规则 — ChatGPT + AI + Git 协作机制

> 生效日期：2026-09-17 ｜ 适用项目：钢结构出口加工厂 MES

## 一、角色分工

| 角色 | 职责 |
|------|------|
| **ChatGPT** | 架构审查、业务规则确认、数据库设计审查、重大技术决策、代码审查 |
| **AI 执行者（TraeCode）** | 读取项目、编写代码、数据库迁移、API、测试、本地验证 |
| **Git** | 双方共享的项目唯一事实来源 |

## 二、每次任务完成后的固定流程

1. 更新 `AI协作/01_当前状态.md`
2. 更新 `AI协作/04_AI执行记录.md`
3. 更新 `AI协作/06_交接给ChatGPT.md`
4. `git status`
5. `git diff`
6. 运行相关测试
7. `commit`（提交信息说明"为什么"）
8. 如已配置远程仓库，再 `push`

## 三、红线（不可越过）

1. **未经 ChatGPT/人工确认，不得自行改变已经冻结的架构。**
2. 业务规则不明确时，写入 `AI协作/05_问题待确认.md`，**不自行猜测**。
3. 严格分阶段推进，前阶段未经审查通过不得进入后阶段：
   - 第一阶段：数据库领域模型（已完成，冻结待审）
   - 第二阶段：database_design_v1.2.md 详细设计（表/字段/约束/索引）
   - 第三阶段：SQL / Migration
   - 第四阶段：后端代码 / API
4. 不得替业务方（老板）拍板任何待确认事项。
5. 事实保护：任何阶段不得设计或编写"直接覆盖原始业务事实"的逻辑。

## 四、当前业务依据（权威顺序）

1. **最高依据**：`docs/v1.2_business_decisions_v2.md` 第六轮最终收口 / Part 20「V1.2 最终收口与业务冻结候选输出」
2. 第一阶段交付物：`docs/v1.2_database_domain_model.md`（902 行，20 章）
3. 前五轮业务内容仅作历史参考，与第六轮冲突时以第六轮为准。
4. N-10（BOM 模板→零件实例）、N-23 原则（事实更正不可管理员覆盖）等为**已确认**，不得回到待确认。
